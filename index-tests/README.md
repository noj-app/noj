# اختبارات index.html (تطبيق نوج)

اختبارات Playwright تفتح `index.html` فعلياً في Chromium حقيقي، بلا أي اتصال شبكة حي —
عميل Supabase مزيَّف بالكامل (`fake-supabase.js`) يُحقَن عبر `window.__NOJ_SUPABASE_CLIENT__`
(نقطة الحقن الموجودة أصلاً في `getSb()`)، وجلسة محفوظة مسبقاً (`noj_session`) فيُقلع التطبيق
مباشرة على بيانات العميل.

## التشغيل

```
cd index-tests
npm install
npm test
```

## ما تغطيه (الحجوزات — supabase-migration-reservations.sql)

١. مطعم فعّل الحجوزات: قسم "حجوزات"، نموذج (التاريخ، الوقت، عدد الأشخاص، ملاحظة اختيارية)،
   تحقق محلي قبل أي نداء، وإرسال فعلي عبر `create_reservation()` — الوقت المختار يُرسَل
   بتوقيت الرياض ويُعرض بتوقيت الرياض حتى لو كان الجهاز على توقيت آخر (اختبار بجهاز على
   توقيت نيويورك).
٢. أخطاء الخادم (مثل حد 3 حجوزات) برسالة عربية والنموذج يبقى بقيمه.
٣. الخدمات: نوع الخدمة بدل عدد الأشخاص.
٤. الحجوزات القائمة تُحمَّل عند الدخول (القادمة فقط، بانتظار/مؤكَّد)، تُلغى عبر
   `cancel_appointment()` (نفس دالة مواعيد الصحي)، وتبقى ظاهرة إن أوقف التاجر الحجوزات.
٥. فتح القسم يحدّث الحالة (التاجر قبل الطلب).
٦. الصحي ("مواعيدي") والمقهى بلا أي تغيير: نفس الاستعلام، نفس الأزرار، نفس التوست التجريبي.
٧. الخدمات: القائمة من خدمات التاجر المفعّلة والمفتوحة للحجز فقط (لا نص حر)، وخدمة أُغلقت بعد فتح النموذج تُرفض
   برسالة وتُحدَّث القائمة.
٨. سياسة الإلغاء: زر الإلغاء يختفي حين يمنعه التاجر أو بعد مهلة القفل، مع السبب، ورفض الخادم يظهر برسالة واضحة.

## الدخول (auth_tests.js) — بعد عطل حي: عميل مسجَّل لا يدخل من جهاز جديد

`npm test` يشغّل الملفين معاً. ودجت Turnstile مزيَّف (`fake-turnstile.js`) وSupabase Auth مزيَّف
(`fake-auth-supabase.js`) يفرض قواعد GoTrue التي اعتمد عليها العطل: رمز CAPTCHA يُقبل مرة واحدة فقط،
`phone_exists` عند updateUser لرقم مملوك، "Signups not allowed for otp" عند `shouldCreateUser:false` لرقم
بلا حساب، ونوع التحقق يجب أن يطابق مسار الإرسال (`sms` / `phone_change`).
١. عميل جديد: جلسة مجهولة ← signInWithOtp(shouldCreateUser:false) يُرفض ← updateUser ← تحقق phone_change.
٢. عميل موجود من جهاز جديد (حالة الآيفون): لا updateUser إطلاقاً، تحقق sms، يدخل حسابه نفسه، ثم
   claim_or_create_verified_profile ثم claim_unclaimed_invoices.
٣. عميل موجود وجهاز عليه جلسة مجهولة (حالة اللوحي): طلب CAPTCHA واحد فقط.
٤. الأرقام العربية والفارسية في خانة الجوال وخانات الرمز.
٥. كل طلب إرسال (وإعادة إرسال) برمز Turnstile مختلف؛ ودجت أبطأ من مهلة 2.5 ثانية القديمة؛ ودجت يعيد
   الرمز نفسه بعد reset لا يُرسَل منه الرمز مرتين.
