# اختبارات merchant.html (لوحة التاجر — المرحلة الأولى: الدخول + شاشة الأجهزة)

اختبارات Playwright تفتح `merchant.html` فعلياً في Chromium حقيقي، بلا أي اتصال شبكة حي —
عميل Supabase مزيَّف بالكامل (`fake-supabase.js`) يُحقَن عبر `window.__NOJ_SUPABASE_CLIENT__`
(نفس نقطة الحقن التي يوفّرها الملف أصلاً للاختبار، راجع `getSb()`)، فتُجاب كل نداءات
`auth`/`rpc`/`from` من بيانات داخل الذاكرة يتحكم بها الاختبار نفسه.

**خاصية واحدة مختلفة عن `kiosk-tests/`**: جلسة الدخول هنا تُكتَب فعلياً إلى `localStorage`
الحقيقي للمتصفح (تحت `storageKey` المُعطى، أو `sb-noj-merchant-auth` افتراضياً) — لا ذاكرة JS
بحتة — تحديداً لأن اختبار عزل الجلسات (رقم 9) يحتاج دليلاً حقيقياً على أن مفتاح تخزين تطبيق/كشك
آخر لم يتغيّر، لا افتراضاً مبنياً على عميل مزيَّف لا يلمس `localStorage` إطلاقاً.

## المتطلبات

- Node.js + الحزم في `package.json` (`npm install`) — تُثبَّت حزمة `playwright` فقط (بلا
  إعادة تنزيل متصفح Chromium، المُثبَّت مسبقاً في بيئة هذا المشروع).

## التشغيل

```
cd merchant-tests
npm install
npm test
```

## ما تغطيه

٠. ثبات `storageKey`: القيمة الحرفية في `merchant.html` تطابق القيمة المتوقَّعة فعلياً.
١. دخول ناجح: رقم جوال + رمز صحيحان → شاشة اللوحة، باسم التاجر ظاهراً.
٢. رمز خاطئ: رسالة خطأ عربية واضحة، لا انتقال للوحة.
٣. لا صلاحية: جلسة ناجحة بلا صف `merchant_members` → شاشة "لا تملك صلاحية وصول"، بلا أي بيانات.
٤. خطأ اتصال فعلي أثناء التحقق من الصلاحية → رسالة مختلفة ("تعذّر التحقق") مع زر إعادة محاولة،
   لا نفس رسالة "لا صلاحية" القاطعة.
٥. شاشة الأجهزة: اسم الفرع، حالة "فعّال"، ووقت آخر نشاط من `devices.last_seen_at`.
٦. اعتماد كشك جديد: رمز وفرع صحيحان → الجهاز يظهر في القائمة فوراً، و`approve_device_pairing`
   استُدعيت بالمعاملين الصحيحين فعلياً (لا افتراضاً).
٧. اعتماد برمز خاطئ: رسالة خطأ واضحة، لا جهاز جديد يُضاف.
٨. إلغاء جهاز: نافذة تأكيد تظهر أولاً (لا تنفيذ بالضغطة الأولى)، التراجع يُلغي بلا أي تغيير،
   التأكيد يحدِّث الحالة فعلياً إلى "مُلغى" ويضبط `is_active=false`/`revoked_at` في التحديث الفعلي.
٩. **عزل الجلسات**: مفتاح `localStorage` يمثّل جلسة `index.html`/`kiosk.html` حقيقية (نفس اسم
   المفتاح الافتراضي الذي يستخدمه `supabase-js` على هذا المشروع) يُزرع قبل تحميل `merchant.html` —
   يُفحَص بعد دخول كامل للوحة أنه **بلا أي تغيير حرفي**، وأن جلسة اللوحة نفسها تحت مفتاحها
   المخصَّص منفصلة تماماً.
١٠. مؤقت الخمول: بعد انتهاء المهلة (مختصَرة للاختبار عبر `window.__NOJ_IDLE_MS__`)، خروج تلقائي
    وعودة لشاشة الدخول.
١١. جلسة محفوظة مسبقاً: إعادة تحميل الصفحة بجلسة صالحة تنتقل مباشرة للوحة بلا إعادة إدخال الرمز.

## ملاحظة مهمة

هذه اختبارات **واجهة** (كل منطق الحماية/الصلاحيات الفعلي يبقى في قاعدة البيانات، مُختبَر في
`db-tests/`) — تتحقق فقط أن `merchant.html` يستدعي الدوال الصحيحة بالمعاملات الصحيحة ويعرض
استجاباتها بشكل صحيح، لا أكثر. لا تُشغَّل تلقائياً في أي مكان بعد — تُشغَّل يدوياً فقط.
