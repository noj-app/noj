# اختبارات kiosk.html (مرحلة ٣ — الالتقاط المباشر لعمليات POS)

اختبارات Playwright تفتح `kiosk.html` فعلياً في Chromium حقيقي، بلا أي اتصال شبكة حي —
عميل Supabase مزيَّف بالكامل (`fake-supabase.js`) يُحقَن عبر `window.__NOJ_SUPABASE_CLIENT__`
(نفس نقطة الحقن التي يوفّرها الملف أصلاً للاختبار، راجع `getSb()`)، فتُجاب كل نداءات
`auth`/`rpc`/`from`/`channel` من بيانات داخل الذاكرة يتحكم بها الاختبار نفسه.

## المتطلبات

- Node.js + الحزم في `package.json` (`npm install`) — تُثبَّت حزمة `playwright` فقط (بلا
  إعادة تنزيل متصفح Chromium، المُثبَّت مسبقاً في بيئة هذا المشروع).

## التشغيل

```
cd kiosk-tests
npm install
npm test
```

## ما تغطيه

١. وصول عملية `pos_transactions` حقيقية عبر Realtime (`postgres_changes` INSERT) — انتقال
   تلقائي من شاشة الانتظار إلى شاشة الطلب بالمبلغ الحقيقي، لا قيمة القالب الثابتة.
٢. عميل مسجَّل: `kiosk_claim_pos_transaction` تُرجع `is_registered=true` — شاشة النجاح تعرض
   الرصيد الحقيقي (سابق + مضاف = إجمالي) من استجابة الخادم فعلياً، لا تقديراً محلياً.
٣. عميل غير مسجَّل: رسالة "حُفظت فاتورتك" واضحة بدل أي بطاقة رصيد/نقاط مزيَّفة.
٣ب. عملية ثانية تصل أثناء عرض الأولى لا تقاطعها، وتُعرَض تلقائياً من الطابور بعد انتهاء الأولى.
٤. انتهاء صلاحية العملية (`expires_at`) قبل أي تفاعل — رجوع تلقائي لشاشة الانتظار.
٥. انقطاع Realtime (`CHANNEL_ERROR`) مع التقاط الاستعلام الاحتياطي الدوري لعملية جديدة بدل
   التعليق إلى الأبد (`window.__NOJ_POLL_MS__` تُقصِّر فترة الاستطلاع للاختبار فقط).
٦. الوضع التجريبي لم يتغيّر إطلاقاً: زر "التالي (تجربة)" يعمل بمبلغ القالب الثابت كما كان،
   ويختفي تماماً في الوضع المباشر، وشاشة النجاح لا تزال تعرض بطاقات okItems الإضافية (لم تُخفَ
   إلا في الوضع المباشر فقط).
٧. القناة `SUBSCRIBED` منذ البداية: الحدث يصل فعلياً عبر Realtime لا الاستعلام الاحتياطي —
   يتحقق من عدّاد poll مخصَّص في `fake-supabase.js` (`__TEST__.getPollCount()`) يبقى صفراً.
٨. سطر التشخيص في شاشة إعدادات الجهاز (حالة القناة + وقت آخر حدث Realtime، بلا أي بيانات
   عميل) يظهر ويتحدَّث تلقائياً بعد وصول حدث فعلي.
٩. تجديد توكن الجلسة (`TOKEN_REFRESHED`): يُمرَّر التوكن الجديد لـ `realtime.setAuth()`
   صراحة، وتُعاد إعادة الاشتراك بقناة جديدة فعلياً (لا الاعتماد وحده على الربط الداخلي
   الضمني في supabase-js) — والعمليات الجديدة لا تزال تصل بعدها.
١٠. الوضع المباشر: شاشة النجاح لا تعرض "رقم دورك"/"رقم طلبك"/"موعدك القادم" (بلا مصدر حقيقي
    بعد) — يبقى فقط "فاتورتك" ونقاط الولاء.
١١. تنظيف: قسم "الربط بنظام الكاشير" القديم (رمز إقران مُدخَل يدوياً + زر "اختبار الاتصال"
    المزيَّف بالكامل) غائب تماماً عن شاشة الإعدادات — لا عناصره ولا نصّه.
١٢. الوضع (demo/live) يُقرأ من `branch_settings.pos_mode` لا من `localStorage` وحده — جهاز
    demo محلياً يرث فعلياً live من صف فرعه عند أول إقلاع.
١٣. حفظ الوضع من شاشة الإعدادات يكتبه فعلياً إلى `branch_settings.pos_mode` عبر
    `sb.from('branch_settings').update(...)` (يُتحقَّق من الحمولة فعلياً عبر
    `__TEST__.getLastUpdate()`)، والوضع التجريبي (التبديل والحفظ) لم يتغيّر.

## ملاحظة مهمة

هذه اختبارات **واجهة** (كل منطق الحماية/الصلاحيات الفعلي يبقى في قاعدة البيانات، مُختبَر في
`db-tests/`) — تتحقق فقط أن `kiosk.html` يستدعي الدوال الصحيحة بالمعاملات الصحيحة ويعرض
استجاباتها بشكل صحيح، لا أكثر. لا تُشغَّل تلقائياً في أي مكان بعد — تُشغَّل يدوياً فقط.
